## 접근

1. 풍선 `[start, end]`가 주어지고, 한 지점에 화살을 쏘면 그 지점을 구간에 포함하는 풍선이 모두 터진다. 최소 화살 수 = 겹치는 구간을 최대한 묶어서 세는 문제.
2. 겹치는 구간을 묶는 문제라 **끝점 기준 오름차순 정렬**을 한다. 끝점이 가장 빨리 끝나는 풍선의 끝점에 화살을 쏘는 게 항상 이득이기 때문. 그보다 앞에 쏘면 터뜨릴 수 있는 풍선이 줄어들고, 뒤에 쏘면 그 풍선을 놓친다.
3. 첫 풍선의 끝점을 화살 위치 `xend`로 잡고 화살 1개로 시작한다.
4. 다음 풍선의 시작점이 `xend`보다 **뒤에 있으면** 지금 화살로는 못 터뜨리므로 화살을 하나 더 쓰고, 그 풍선의 끝점을 새 화살 위치로 갱신한다.
5. 시작점이 `xend` 이하면 이미 쏜 화살에 같이 터지므로 아무것도 안 한다.
6. 정렬 비교는 `a[1] - b[1]` 대신 `Integer.compare`를 쓴다. 좌표 범위가 `-2^31 ~ 2^31-1`이라 뺄셈은 오버플로로 정렬이 깨진다.

## 풀이

```java
class Solution {
    public int findMinArrowShots(int[][] points) {
        // 끝지점을 기준으로 정렬
        Arrays.sort(points, (a, b) -> Integer.compare(a[1], b[1]));

        int arrows = 1;
        // 끝지점
        int xend = points[0][1];
        for (int i = 1; i < points.length; i++) {
            // 시작지점
            int xstart = points[i][0];
            // 앞선 끝지점 보다 뒤에 시작 지점이 뒤에 있다면 화살이 하나 더필요
            if (xstart > xend) {
                arrows++;
                xend = points[i][1];
            }
        }
        return arrows;
    }
}
```

시간 O(n log n) — 정렬이 지배, 공간 O(1) (정렬 제외)

## 막혔던 부분

1. **끝점 기준 정렬 발상.** 시작점으로 정렬하는 건 바로 떠올랐는데, 그러면 어디에 화살을 쏠지 정할 수가 없었다. "가장 먼저 끝나는 풍선의 끝점에 쏜다"로 바꾸니 뒤는 한 번 훑는 것으로 끝났다.
